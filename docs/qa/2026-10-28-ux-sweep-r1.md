# UX sweep, round 1 (2026-10-28)

A first-time user's walk through `main` at `5002bcc` by an agent: new account, onboarding, client "Acme Shop", site `http://localhost:4400`, a 24-run audit (start `/clean/`, key pages `meta-before-consent`, `consent-default-late`, `pii-in-url`, `no-cmp`, all four scenarios, click IDs and journey; Partial, 28/100, 6 findings) and a second audit whose start page was unreachable. 1440px and 390px, light and dark. Screenshots were kept locally in `/tmp/zinko-ux-r1/` (not committed). No crash, no console error beyond expected 401/404, no horizontal page scroll.

Fix batches: A = Overview and score, B = audit layout, runs and findings, C = Hits and Tag matrix, D = forms, progress, navigation and settings.

## Major

| Id | Batch | Issue | Fix |
|---|---|---|---|
| M1 | B | Runs matrix shows a green check for every completed capture, which reads as "passed" while 8+ of those runs failed critical rules | Call the state "Captured" with a neutral glyph; show the worst failing severity and count per cell; legend: "Captured = the page was loaded and recorded. Open Findings for pass or fail." |
| M2 | A | Overview score area is a wall of text: the unresolved-checks line names every rule (6, or 19), the banner caveat is said twice | "28 / 100 · Critical issues · 6 checks could not run", rule names behind a disclosure, one banner card, a "Start with: <worst finding>" action beside the score, about three lines |
| M3 | A | The score explainer leads with the formula ("weight times 0.5 plus half the share..."), score and rules versions, and a purchase-fields caveat for a rule that did not run | One plain sentence first ("Starts at 100. Each failing check costs points, more for Critical, more when it fails on more pages."); formula and versions in a Details disclosure; rule caveats only when that rule failed |
| M4 | A, B | Accepting a risk changes nothing on the score or the header count ("Findings 6: 5 critical" stays while Open goes to 5) | Show both "Score 28 (all findings) · 31 excluding accepted risks"; the header counts open findings like the Findings tab |
| M5 | C | Hits use unlabelled glyphs: a bare no-entry icon for "Answered locally", two coloured consent dots explained only in a title, a `t` header, "Run #1" without page or scenario | "Time"; the word "Answered locally"; "Ads denied · Analytics denied"; "#1 /clean/ · No interaction"; one legend line |
| M6 | D | Estimate and ETA far off: "about 9 minutes" / "6–13 minutes left" for 4m13s; "3–7 minutes left" for 47s | Calibrate per-run time (about 10 s measured), recompute from actual pace after 3–4 runs, never a range wider than 2x |
| M7 | B | Header stats, partial banner and tabs take about 420px at 1440×900; the findings list starts near y=580 | On tabs other than Overview collapse the header to one line and the partial banner to a pill; list and detail scroll independently below the tabs |
| M8 | B | Finding detail "Where it was seen": long journey URLs wrap to 10 lines, the message column is cut off inside a triple scroll; empty evidence tabs ("Hit 0, Request 0") | Path labels without the query (full URL on hover), two-line rows (page and scenario, then message), hide empty evidence tabs and open the first non-empty one |
| M9 | D, A | An unreachable start page gives partial runs labelled "Left the site" and a normal-looking 37/100 | Reasons that say what happened ("Page did not load (connection refused)", "Page returned 404", "Redirected to another site"); a banner "The start page could not be loaded, so this audit is incomplete" with the score marked incomplete; preflight the start URL on submit |
