## Patterns across the market

1. Two entry styles. The scanners (Usercentrics, CookieYes, Cookiebot, Consentscan) ask for a URL and answer with a list or a risk level. The monitors (Trackingplan, ObservePoint, DataTrue) need an account, a code change, a form or a call, and answer in hours to days. Nobody combines a URL-only start with a verdict per consent scenario.
2. Prioritisation is weak. The CMP scanners give one grade (Low/Medium/High, a 0-100 rating) and a cookie list. Only DataTrue ("recommended fix for each finding"), Consentmo (plain-language fix steps) and Trackingplan (cause plus next step) tell the reader what to do about one failure. None shows a "fix first" order I could verify.
3. Non-technical explanation is mostly absent. Didomi and Usercentrics hedge ("not legal advice"). Consentmo is the best on wording, and it serves merchants, not agencies reporting to clients.
4. White-label is rare: Consentscan (unverified), Tracking Auditor and GA4 Auditor (earlier doc). ObservePoint's share link is unbranded and expires after a year.
5. The first result usually costs a human: a sales form (ObservePoint), a 30-minute call (DataTrue), a customer-success owner (ObservePoint).

## Copy (ranked)

1. **One field, then a result you can read in under two minutes, with the wait shown.** Consentmo's "Checking" state and DataTrue's "nothing to install" set the bar. Zinko already needs only a start URL. Fit: the start page keeps one field, and the new-audit form prefilled defaults stay. Show the time estimate and the first completed run on the Overview while the rest runs (the Overview already refetches through `useAuditRoom`).
2. **A fix for every finding, in the finding's first line, not only in the detail.** DataTrue and Consentmo attach a fix to each item; Trackingplan names the specific trigger to remove. Fit: Findings list rows show title, severity, owner and the first fix step from the stored wording; the report keeps the action plan grouped by owner.
3. **One plain sentence per failure written for the client, next to the evidence.** Consentmo's tooltips on "why this check matters". Fit: the stored "why" on a finding becomes the report's client-facing line (it already exists); add a consistent shape: what happened, on which scenario, what it means. No model decides it.
4. **A visible "starting point, not legal advice" line and a statement of what was not tested.** Didomi and Usercentrics both do it, and it protects the agency. Zinko's "Could not check" and "Not evaluated" vocabulary already does the second half. Fit: report scope section and the share link footer.
5. **A first-audit sample the user can show a client immediately.** ObservePoint's sample audit is a report you receive before you commit. Fit: after the first audit, the Overview offers one next step, "Preview the client report", which opens the report draft; creating the share link follows from there.
6. **Scenario wording shared by the product and the report ("Accept all, Refuse all, No action").** Didomi's reference page explains how the user-behaviour value is derived. Fit: the Overview scenario matrix and the report matrix use the same three plain names, with GPC as a fourth.
7. **Alert delivery to Slack or email, owner-routed.** Trackingplan and DataTrue. Only after scheduling exists; see roadmap.

## Avoid

- **A single grade with no arithmetic** (Usercentrics Low/Medium/High, Didomi 0-100%). Zinko already shows score arithmetic; keep it.
- **A cookie list without a verdict** (CookieYes, Cookiebot). It looks complete and answers nothing.
- **Lead-capture forms and sales calls before the first result** (ObservePoint sample, DataTrue trial). Zinko's advantage is open, immediate and self-serve.
- **Waiting for traffic** (Trackingplan: an hour to a week). A controlled capture gives an answer now.
- **Unbranded or expiring share links** (ObservePoint: one year). Keep revocable, branded links.
- **Legal-sounding verdicts** ("compliant", "non-compliant"). The competitors that hedge are right to; Zinko says what fired, when, under which scenario.
- **A free tier whose limits are unclear** (Consentmo, CookieYes). State limits on the start page.
- **Page-count caps as the headline unit** (ObservePoint 50 or 100 pages). Zinko's unit is runs; the form already estimates time.

## Roadmap suggestions (ranked)

1. **Fix-first line on every finding row and report entry (S).** Show the first stored fix step and the owner in the Findings list and the report's finding card. Uses stored `check_result` wording, so no schema change. Highest return because competitors mostly do not do it.
2. **First-audit guided next step on Overview (S).** When an audit is the organization's first evaluated one, replace the generic content with three steps: read the top finding, accept or note one, preview the client report. Ends on the share link dialog. No new data.
3. **Client-voice sentence and standard disclaimer in the report (S).** One consistent "what happened / what it means" line per finding from the stored `why`, plus the "not legal advice" and "what was not tested" block in the scope section. Needs a validator in `LEAF_VALIDATORS` for any new field.
4. **Sample report on the start page (M).** A static, branded example report (fixture audit, no personal data) before sign-up, so an agency sees the deliverable in under a minute. It reuses `ReportView`, which is already pure.
5. **Slack or email alert on a failed re-run (L).** Only after scheduled audits exist (`roadmap.md` v0.3). It is the one monitoring feature all the paid competitors sell, but it depends on scheduling, so it comes last.
