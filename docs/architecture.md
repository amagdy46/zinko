# Zinko architecture and stack

The stack follows the Ovriq house stack: **Effect 4 on Cloudflare**. See [decision 0001](decisions/0001-effect-and-cloudflare.md). The scaffold is generated by [efforge](https://github.com/amagdy46/efforge); `efforge.jsonc` at the repo root lists the choices (Postgres, Drizzle, better-auth with organizations, Alchemy, Effect AI BYOK, and the workflows, realtime, browser, storage and email add-ons). Add or change parts with `efforge add`, not by hand.

## Shape

```
└──────┬──────────────────────────────────────────▲─────────────┘

       ▼                                           │
┌──── AuditWorkflow (Cloudflare Workflows) ────┐   ┌── AuditRoom (Durable Object, 1 per audit) ──┐
│ step per page × scenario:                    │──▶│ fan-out of run events to open tabs          │
│   Browser.capture(...)  ──────────┐          │   └─────────────────────────────────────────────┘
│   decoders → Hit[] → store        │          │
│ rules(captures) → Finding[]       │          │
│ llm.explain(findings) (BYOK)      │          │
└───────────────────────────────────┼──────────┘
                                    │ POST /capture (packages/capture-contract)
                                    ▼
   ┌── apps/browser — Cloudflare Container (standard-1) ──────────────┐
   │ Node server: /capture, /health, URL policy, limits, 1 at a time  │
   │   ├─ egress proxy: every Chromium connection, SSRF + vendor block│

Postgres (Neon) via Hyperdrive — app data, audits, runs, hits (jsonb), findings
R2 — screenshots, HAR, PDFs
```

## Stack

| Layer | Choice | Why |
|---|---|---|
| Language | TypeScript | One language from crawler to UI |
| Core library | **Effect 4** (`effect@4.0.x`) | Typed errors fit "audits fail partially"; services and layers keep Cloudflare out of the core; one style across Ovriq |
| Cloudflare bindings | **effect-cf** (Effect-native Workers, Durable Objects, Workflows, Queues, R2) | Bindings as layers instead of a global `env` |
| Monorepo | pnpm workspaces + Turborepo | Already set up |
| Web | **TanStack Start** on Workers via `@cloudflare/vite-plugin`, + TanStack Router / Query / Table | Server functions call into one `ManagedRuntime` |
| UI kit | Tailwind v4 + shadcn/ui (Radix) + lucide icons | Owned components, accessible, fast to build |
| Validation | **Effect Schema** | Replaces Zod; shared by server functions, rule config and LLM output |
| Database | **Postgres (Neon) through Hyperdrive**, **Drizzle** (`drizzle-orm/effect-postgres`); `drizzle-kit` generates the migrations, `pnpm db:migrate` applies them | Postgres keeps a non-Cloudflare self-host path open; D1 would not |
| Auth | **better-auth** + organization plugin, on the same Postgres | Workspaces, invites, roles; runs on Workers |
| Orchestration | **Cloudflare Workflows**: one workflow instance per audit, one step per page × scenario | Durable retries per step; replaces pg-boss |
| Live progress | **Durable Object per audit** with hibernating WebSockets | Replaces SSE-from-Postgres |
| Browser | **Scrapling 0.5** (`AsyncStealthySession`, Python, on patchright) in a Cloudflare Container, behind the `Browser` service ([decision 0002](decisions/0002-capture-engine.md)) | Stealth browser launcher; `capture.py` drives the page with the Playwright API (routes, request listeners, cookies, screenshot) rather than Scrapling's `fetch()`. Every capability capture needs works, some through `additional_args`. The bot-protection benefit over plain Playwright is provisional |
| Browser (fallback) | Plain Playwright + Chromium in the same container (`apps/browser/src/engines/playwright.ts`) | Operational fallback, picked per request when Scrapling fails to launch or with `CAPTURE_ENGINE=playwright`, and the comparison baseline. Shares the shim, vendor list and autoconsent bridge; `engine` on the result says which ran |
| Browser (egress) | A per-capture HTTP proxy in the Node server; Chromium starts with `--proxy-server` | Playwright routes never see redirect hops, so the SSRF policy and `blockVendorRequests` are enforced where every connection passes |
| Browser (quick checks) | Browser Rendering (`@cloudflare/playwright`) | Cheap quick checks; optional, not built |
| Consent clicking | **@duckduckgo/autoconsent** (MPL-2.0), injected in the container | Deterministic accept/reject for common CMPs |
| Files | **R2** | Screenshots, HAR, PDFs |
| LLM | **`effect/ai`** (Effect 4) with the Anthropic, OpenAI and OpenRouter providers; Ollama through the OpenAI-compatible client | Bring your own key, encrypted per workspace; audits work without a key |
| PDF | The container prints the report route with `page.pdf()` | Reuses the browser |
| Email (invites) | Cloudflare Email Service | Same platform |
| Lint / format | **Vite+**: oxlint and oxfmt, plus the Effect language-service diagnostics | One `vp check` for format, lint and types |
| Infra as code | **Alchemy** (`alchemy@2`, "Infrastructure as Effects") in `infra/alchemy.run.ts`: `Cloudflare.Website.Vite` for TanStack Start, Workflows, Durable Objects, Containers, R2, Hyperdrive, plus the Neon project and branches | Infra in TypeScript and Effect, same as the app; no hand-written `wrangler.jsonc`; a Neon branch + Worker per PR preview |
| CI / deploy | GitHub Actions: check, typecheck, build, `alchemy deploy` (per-PR stage, destroyed on close) | |

## Packages

```
apps/
  web/          generated: TanStack Start on Workers (UI, server fns, auth, realtime, workflows); will host AuditWorkflow and AuditRoom
  browser/      Zinko: the capture container image (Node server, egress proxy, Scrapling engine in scrapling/, Playwright fallback)
  cli/          Zinko: `decode` and `capture` (against the engine), rules later, no Cloudflare
packages/
  core/         generated: Effect service interfaces (Database, Auth, Storage, Llm, Browser, ...)
  db/           generated: Drizzle schema, migrations, Effect SQL layer
  decoders/     Zinko: request -> Hit (GA4, Google Ads, Meta, TikTok; pure TS, no Effect)
  capture-contract/  Zinko: Effect Schemas for POST /capture, shared by the web app and the CLI
  fixtures/     Zinko: fake shops, each with one known tracking bug, plus a server and an `inspect` script
infra/
  alchemy.run.ts  generated: every Cloudflare resource, per stage
planned: packages/rules, llm, plan
```

Zinko's own packages (`decoders`, `capture-contract`, `cli`) are plain TypeScript and follow the workspace's TypeScript 7, catalog dependencies and `vp check` rules (including `no-console`; the CLI writes through `process.stdout`).

### Where Effect goes

- **Pure code stays plain:** decoders and rules are pure functions, and stay easy to test and reuse in the CLI.
- **Effect at the edges:** anything with I/O, retries, timeouts or failure modes (capture, DB, R2, LLM, workflow steps) is an Effect service in `packages/core`, with a Cloudflare layer in `apps/web` and a Node layer in `apps/cli`.
- **Error codes are tagged errors:** `BotBlocked`, `Timeout`, `CmpNotFound`, … map 1:1 to the partial-failure codes shown in the UI.

## Data model (v0.1)

```
organization ─< member >─ user              (better-auth)
organization ─< client ─< site ─< audit ─< run (page × scenario × viewport)
                                     │         ├─< hit        (decoded, jsonb params)
                                     │         ├─< datalayer_push
                                     │         └─ artifacts (R2 keys: screenshot, har)
                                     ├─< finding (rule_id, severity, evidence refs, status, llm_explanation)
                                     └─ report_share (token, revoked_at)
organization ─ llm_credential (provider, encrypted key, model)
organization ─ branding (logo, accent, report footer)
```

## Key design rules

1. **Findings are deterministic.** Each rule is a pure function, checked against the fixture sites. The LLM explains findings and suggests fixes but never decides pass or fail, and its output is cached per finding.
2. **Every finding cites evidence:** hit IDs, the request URL, a screenshot, and a cookie snapshot.
3. **Vendor matchers are data plus small decoders,** so endpoint changes are one-line fixes.
4. **Crawled pages are untrusted.** Their content goes to the LLM only as quoted evidence. The agent gets no credentials, and navigation is restricted to an allow-list of the site's domains.
5. **Read-only by default** toward GTM, GA4 and Meta when connectors arrive in v0.2.
6. **Audits fail partially, not completely.** Each page × scenario is its own workflow step; a failed step records a tagged error and the report still renders.
7. **No Cloudflare in the core.** `packages/*` never import Workers types; only `apps/web` does. That keeps the CLI and a future Node self-host target possible.

## Self-hosting

- **v0.1:** deploy to your own Cloudflare account with `alchemy deploy` (Neon, or any Postgres URL for Hyperdrive). Free-tier friendly except Containers, which need Workers Paid.
- **Later:** a Node target (`@effect/platform-node` layers + Docker Compose) using the same packages, if self-hosters ask for it.

## Testing

No unit or integration tests in the current phase: we verify by running the real thing (the CLI, the engine, a capture against a fixture site). See "Current phase" in [AGENTS.md](../AGENTS.md).

## Open questions

- **Bot protection:** Scrapling vs plain Playwright vs patchright on 5 bot-protected sites: does the page load like a real visitor's and do the tags fire? Pending: it needs 5 sites the user has approved, and until then decision 0002 treats Scrapling's stealth benefit as provisional.
- How bot-protected sites treat traffic from Cloudflare Containers (datacenter IPs either way, but no bot signature).
- Container cold start and cost for 10 pages × 3 scenarios; whether one container per audit with many tabs beats one per step. The engine runs one capture at a time per container and launches a browser per scenario.
