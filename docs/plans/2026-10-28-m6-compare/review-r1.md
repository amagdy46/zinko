# M6 plan review, round 1 (GPT-6.1 Sol, high) — verdict: needs rework

The main gaps affect comparison truthfulness and demo safety.

1. **Blocker — dropping failing cells can produce "Fixed".** (P:140–147.) Baseline A fails, B fails; current A passes, B missing: intersecting first discards B and declares Fixed. `banner_differs` removal does the same; mixed prior unknown/pass cells can become unqualified New (`rules-schema.ts:23`, `Audit.ts:601`). Change: keep every previously failing cell when deciding verified fixed; tell partial confirmation from complete resolution; specify mixed-verdict precedence. Verify: removed page, missing viewport, failed capture, banner mismatch, mixed unknown/pass, expectations written first.
2. **Blocker — the demo's central mutation guard blocks reads and misses writes.** (P:200, 394–398.) `read()` calls `respond()` (`server-fn.ts:51`); AI-setting mutations use `runtime.runPromise` directly (`ai-settings.ts:75,96,110`); Better Auth runs through its own Worker route (`auth-route.ts:7`). Change: an explicit mutation gate before side effects, a deny-by-default Better Auth policy allowing only needed auth and session operations, an inventory of every server function and Worker route. Verify: direct requests for uploads, publish/delete snapshots, share create/revoke, AI operations, account deletion, organization create/delete; reads still work.
3. **Blocker — comparison details can bypass "Leave out".** (P:162–176, 345–351.) `changes` ignores report exclusions, so a hidden finding reappears with state, severity and page counts (`AGENTS.md:160`, `report-data.ts:501,681`). Change: project changes through the current audit's exclusions, briefing lines included; define baseline-only fixed findings. Verify: hide a new, a regressed and a fixed finding; draft JSON, snapshot and public HTML show no detail.
4. **Should fix — a site lock cannot enforce an organization-wide cap.** (P:245–248.) Creates on different sites lock different rows (`server-fn.ts:71–79`, `audits.ts:149–159`). Change: serialize per organization across every creation path; revalidate the baseline inside; define whether changing `baseline_audit_id` can evade the in-progress guard. Verify: concurrent creates across two sites at four active give exactly five; race same-baseline re-runs and baseline deletion.
5. **Should fix — cell identity omits capture context.** (P:47, 50, 140–142, 156.) A scenario name does not establish the consent outcome; `not-applied` differs from accepted/rejected (`capture-contract/src/index.ts:157–169`); banner detection only annotates `none` (`consent-context.ts:29–32,69`). Change: consent outcomes in cell comparisons, consent-sensitive verdicts gated; click-ID settings in applicability; ordered journey identity. Verify: accept applied vs not applied, desktop and mobile, reordered journeys, click IDs toggled.
6. **Should fix — regression history is audit-level, not cell-level.** (P:148.) An old mobile checkout failure can label a new desktop homepage failure "Regressed"; `finding.kind` aggregates runs (`Audit.ts:601–626`). Change: historical failure on the newly failing comparable cells, with baseline pass, applicability and version checks; define chronological vs baseline-ancestry ordering. Verify: unrelated scopes, branched chains, unknown intermediates, deleted historical audits.
7. **Should fix — fixed changes cannot use the confirmation endpoint.** (P:308, 321.) A fixed rule has no current `finding` row, so `verifyFinding(currentAudit, ruleId)` fails; `finding.run_ids` includes inconclusive runs (`rules-schema.ts:73`, `Audit.ts:626`). Change: confirm from an authorized comparison's explicit target cells, baseline-only findings supported; enough target identity to separate overlapping verifications. Verify: confirm Fixed, New, mixed fail/unknown; incomplete confirmation never reads as a pass.
8. **Should fix — carry-over provenance vs mutable baselines.** (P:53, 101–103, 259, 280.) Copy-on-creation fits; but changing the comparison baseline leaves another audit's copies, deleting the origin nulls the only marker, and `coalesce` can misattribute. Change: inheritance source independent of the comparison baseline, provenance kept after source deletion, disclosed; amend both triage and report-edit writer rules (`AGENTS.md:94,160`). Verify: copy, change baseline, delete origin, re-run again.
9. **Should fix — skipping the Container breaks initialization.** (P:394.) `AppLayer` builds `BrowserLive` on every request (`runtime.ts:12–13`, `layers.ts:24`), which needs `BROWSER_ENGINES` and the Container namespace without `BROWSER_URL` (`browser.ts:76,98–104`). Change: a demo runtime composition that boots without capture and refuses capture explicitly. Verify: deployed sign-in, authenticated reads, public report without a Container binding.
10. **Should fix — reports lose confidence qualifications.** (P:165–176.) Frozen changes omit confidence and confirmation. Change: project and freeze the qualification, or omit uncertain claims; the publication stamp covers every mutable comparison dependency, regression history included (`report-data.ts:260`, `report-publish-data.ts:50`). Verify: low-confidence publication, later confirmation and history changes, the earlier snapshot unchanged.

Change: equivalent scope and context for an unqualified delta; say both use current arithmetic. Verify: complete audits with different pages or viewports; a score-version transition.

Task 4 copies `include_changes` before Task 11 adds it; the flaky counter reset cannot show two flips over three audits, and preflight loads the page (`audits.ts:147–148`); maximum-size baselines are measured after the integrations they baseline.
