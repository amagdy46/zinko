# Capture capabilities plan review, round 1 (GPT-6.1 Sol, high) — verdict: needs rework

The architecture fits, but several rule predicates and verification expectations are not implementable reliably as written.

1. **Blocker — banner observation runs too early.** P:78 starts one check at navigation commit; the shim returns `null` before document completion or CMP detection, and awaiting that resolved promise never retries (`apps/browser/src/inject/datalayer-shim.js:193–201`). Python checks frames sequentially, so its bound is not 2 s (`apps/browser/scrapling/capture.py:799`). Change: poll within one bounded, document-specific window; keep watch-only configuration and action dispatch separate. Verify: delayed CMP, delayed iframe, cookie-restored consent, zero extra opt-in/out actions, both engines.
2. **Blocker — "accepted" does not mean every Google signal was granted.** P:189, P:227 fail on denied state after acceptance without establishing the same signal was granted before. Acceptance allows either ad or analytics storage to match (`playwright.ts:698–706`); `consentTimeline` marks only the action boundary (`packages/rules/src/consent-state.ts:17`). Change: compare post-choice signals with the corresponding settled arrival signals; missing signals stay unknown; banner recurrence is observed behaviour, no cookie cause asserted. Verify: mixed grants, delayed updates, template-only signals, legitimate page-specific prompts.
3. **Blocker — same-site and consent-cookie inference are unsound.** P:112, P:224 call any newly appearing non-analytics cookie a consent cookie and infer registrable domains from a short suffix list; session and cart cookies qualify; existing consent cookies may only change value; the first document has `document-end`, not `end` (`capture-contract/src/index.ts:104–112`). Change: a maintained PSL with private suffixes, or unknown where the relationship is unproven; separate domain relationship, cookie reachability and CMP-cookie identification. Verify: `co.uk`, private-suffix tenants, changed cookies, localStorage consent, path-restricted cookies (`rules/src/cookies.ts:29–48`).
4. **Should fix — linker verdicts need matched destinations and arrival evidence.** P:229 compares GA4 client ids without matching measurement ids or resolving multiple hits; `_gl` can sit on an intermediate redirect or vanish through history changes; recorded URLs are request-time (`playwright.ts:181–194`). Change: compare corresponding GA4 destinations, define every `_gl`/identity outcome, verify the click reached the intended host. Verify: multiple streams, redirect decoration, JS-intercepted clicks, SPA transitions, `_gl` present but identity changed.
5. **Should fix — CLI journey detection and old captures.** P:20, P:202, P:227 promise old captures become inconclusive, but a missing `navigation` reads as "no reload/follow", so not applicable; the CLI recognises only `goto` as a journey (`apps/cli/src/index.ts:275`, `:401`). Change: update both CLI consumers; distinguish unsupported metadata from an observed absent step. Verify: follow-only, reload-only, saved pre-change captures through `evaluateRun` and the CLI digest.
6. **Should fix — purchase expectations contradict the fixtures.** P:204 promises four cited vendors and reject not applicable; Meta and TikTok fixtures send no transaction id (`fixtures/shared/tags.js:149`, `:168`); Google purchase commands run on thank-you regardless of consent (`:78–82`); `transactionId` reads only `params.transaction_id` (`rules/src/purchases.ts:43`). Change: settle supported identifiers and per-vendor outcomes; compare destination as well as vendor and order id; amend fixtures or decoder scope explicitly.
7. **Should fix — "last key page" is inaccurate.** The workflow visits only five key pages (`Audit.ts:317–319`) of up to twenty (`core/src/audit.ts:12–14`). Change: "last visited journey page", exposed, or an explicit reload target. Verify with more than six configured pages.
8. **Should fix — per-step worst case.** P:84 claims 15 s, but navigation alone allows 30 s plus observation up to 10 s (`playwright.ts:60–69`); the 180 s cap fits the 4-minute step and 5-minute lease but may truncate before reload. Change: separate total deadline from step guarantees, with startup, finalization and storage margins. Verify: slow six- and eight-step captures through the workflow, including timeout and grant release.
9. **Should fix — initiator joining needs an unmatched-event policy.** P:126 assumes equal ordering between context-wide requests and page-session CDP events; OOPIF requests enter the context listener (`playwright.ts:958`); late events must mark checkpoint rows dirty (`:513–519`). Change: correlate by target and frame, define late and unmatched records, unknown on ambiguity. Verify: identical URLs from main frame and OOPIF, redirects, blocked requests.
10. **Should fix — initiator storage understated.** Eight 300-character frames plus a URL per record; 500 records can pass 1.2 MB, and checkpoints count against the 10 MB budget (`capture.ts:35`, `:61`). Change: aggregate byte limits, bounded pending joins, attribution-specific truncation. Verify: maximum stacks and repeated checkpoints.
11. **Should fix — vendor-wide attribution can name the wrong loader.** P:130, P:249 pick one SDK per vendor; `RunInput` has request and document identity for narrower attribution (`rules/src/types.ts:10–26`); `clean` inserts gtag dynamically from `tags.js`, contradicting P:252's `page` classification (`tags.js:35–38`). Change: attribute cited requests, multiple or unknown when needed; correct the baseline.
12. **Should fix — task dependencies and sizing.** Task 2's reload verification precedes Task 3's workflow wiring (P:193, P:198); Task 4 bundles migration, authorization, settings UI, two engines, CLI and run planning. Change: wire the workflow earlier; split Task 4 (settings and schema, then follow and run integration); make watch-only and Scrapling initiator feasibility explicit gates; snapshot measured hosts when the audit is created (`Audit.ts:134–146`).

Cleared: main-frame Fetch interception guards redirect hops (`playwright.ts:333–401`); the proxy resolves and connects to checked addresses (`egress-proxy.ts:207–219`). Extend P:217 verification to both engines, HTTPS redirects, DNS rebinding and mixed answers, credentials, deceptive host suffixes, and `*.localhost` with private access off.
