# M5 Report Plan

**Goal:** A consultant opens a finished audit, lands on a Report tab that shows what the client will read (cover, one-page summary, scope and method, a consent-scenario summary, findings with stored wording and one safe evidence item, an action plan grouped by who fixes it, an appendix), edits the summary and adds notes, then shares it as a revocable link with the agency's logo, accent colour and footer, saves it as a PDF, or exports a CSV register. Demo: "Send a white-label report to a client" (`docs/roadmap.md`, M5).
**Approach:** The report is a read model over rows M3 and M4 already write (`finding`, `check_result`, `hit`, `run`, `finding_triage`, the score and Overview queries). It is built on read, in one consistent database snapshot, into a `ReportModel` that passes through a **report-specific disclosure projection** (below): every field is either static reviewed wording, a count, a value from a fixed list, or text the consultant typed. Nothing that a site, a hit or a capture could have written reaches the model unless the projection names it. The consultant's work is stored apart from derived rows: `org_branding` (per organization), `report_edit` and `report_finding_edit` (per audit, like `finding_triage`, never touched by the workflow). A share link points at a **frozen snapshot** (`report_snapshot`) copied under a publication lock, so a client sees what the consultant published on a date. The public page is a **Worker route under `/r/`** that reads only that row and renders static HTML with no JavaScript framework, which gives one place that decides status codes, headers, logo access and abuse controls. The link holds a 256-bit secret of which only the SHA-256 is stored. PDF is the browser's print of the same page; a server-rendered PDF is deferred. The trade-off: a snapshot can go stale (the Report tab says so by comparing a publication identity that includes the logo bytes), and a new version needs a new link; in return the record is dated, immutable, cheap to serve, deletable, and cannot leak a later edit. The supported maximum is the M4 one, 168 runs; Task 15 measures the draft build, publication and public read against it.

## Global constraints

- **No unit or integration tests** (`AGENTS.md`, current phase). Each task is verified by running the real thing: the dev server in a browser at 1440x900 and 390x844, both themes through the real theme menu, `psql`, `curl -i`, a real spreadsheet, and for print a throwaway Playwright script in `$TMPDIR` (not committed). Report the command and what was seen. Screenshots go to `$TMPDIR/m5t<task>-*.png` (`TMPDIR=$HOME/.cache/tmp`).
- `pnpm check && pnpm typecheck && pnpm build` exit 0 with zero warnings after every task (real exit codes).
- **Docs move with the feature.** Every task ends by updating the matching row in `docs/vision.md` ("Report (M5)") and, where it applies, `docs/ui.md` and `AGENTS.md`. Task 16 only sweeps and closes.
- **Rules decide; wording is stored.** The report prints the static wording stored on `finding` and `check_result` (title, why, fix, check title, owner), never the live registry. It **never prints `check_result.message`** and never prints capture error text: those are diagnostics built from the page (see the disclosure projection).
- **Never print personal data: the disclosure projection is the contract.** One pure module, `apps/web/src/lib/report-projection.ts`, owns every function that turns stored data into a report string (`pageLabel`, `destinationLabel`, `eventLabel`, `failureLabel`, `runReasonLabel`, `vendorLabel`, `evidenceRows`). Report builders, the snapshot writer and the CSV writer call only these. Before a model is returned, `assertProjected(model, detail)` validates it **field by field**, fail-closed: it enumerates every leaf path of the model and requires a registered validator for that path (an unregistered path, such as a field added later without review, fails). The validators: `count` (non-negative integer); `amount` (a finite non-negative number, for score values that can be fractional: `score.total`, `score.lines[].points` and the other `HealthScore` arithmetic fields, `apps/web/src/lib/health-score.ts:93,101`); `flag` (boolean); `nullable(v)` (null or `v`); `enum` (a fixed set: severity, area, scenario, viewport, timing, consent state, owner id, triage status, accent id, band); `digest` (`^[0-9a-f]{64}$`, the logo digest); `date` (ISO); `stored` (stored rule wording from `finding` and `check_result`: title, why, fix, check title; length-bounded, trusted by origin because it is static text written in the repository); `vendorLabel` (a `VENDOR_LABELS` value or "Other vendor"); `event` (`knownEvent` or "custom event"); `pageLabel` (Standard: `^(Journey from )?Page \d{1,2}( \(start page\))?$`; Detailed: `^/[^?#\s]{0,119}$` with no `://`, which deliberately **allows** encoded characters and name- or token-like segments because the consultant opted in after reading the list of exact strings); `destination` (Standard: `^G-[A-Z0-9]{4,12}$` or `^AW-\d{6,17}$`, or absent; Detailed: any ID that matches its vendor format in `vocab.ts`, digit-only Meta and TikTok IDs included); `author` (a string within its length cap, printed as typed; the author paths are `summary.text`, `findings[].note`, `findings[].triage.reason`, `branding.agencyName`, `branding.footerText`, `cover.clientName`, `cover.siteName`). Task 4 lists every leaf path of `ReportModel` with its validator in one table (booleans, nullable values and generated strings such as headlines included) and checks that a fractional-score report renders while an unregistered path fails. There is no generic scan of generated strings for digit runs or hex, because that rejects required output (a 64-character logo digest, a long Google Ads ID, a Detailed path). A failing validator is a defect (the report does not render), never a silent drop.
- **Org scoping and the 404 rule.** Every management query filters by `org_id` and reaches runs, findings and hits through `auditInOrg(orgId, auditId)`; snapshots and links by `shareInOrg(orgId, id)`. An id from another organization is a 404, never a 403. The public path has no organization: its only key is the token.
- **Roles on the server.** Branding is owner/admin only (`isManager(role)`). Any member may edit report text, hide findings, change the disclosure level, publish, create and revoke share links and export the CSV. Deleting a published version is allowed to owners and admins and to the member who published it (open question 12).
- **Derived rows.** Nothing new is a derived row. `report_snapshot` and `report_share` are records of a human act (surrogate ids, `defaultNow()` are fine); `report_edit`, `report_finding_edit` and `org_branding` are people's work and the workflow never touches them (`rg "report_|org_branding" apps/web/src/workflows` stays empty). `check_result.owner` is written by `persist-<n>`, `finding.owner` by `finish` from those rows.
- **Vocabulary** (`docs/ui.md`): Critical, Warning, Info; Fail, Could not check, Pass, Not applicable (never "inconclusive"); Open, Accepted risk, Fixed; Not evaluated is never clean; "No failing checks", never "healthy" or "clean". The report never claims a legal verdict.
- **No new dependency.** shadcn components, the shared blocks (`PageHeader`, `EmptyState`, `StatusGlyph`, `SeverityBadge`, `CheckStatusBadge`, `lib/format.ts`), `react-dom` (already a dependency of Start; the public route uses `renderToStaticMarkup`) and `lucide-react`. No PDF, image, QR or markdown library. The logo is validated by reading its first bytes and hashed with Web Crypto.
- **No inline `style` props.** The accent is one of eight presets selected by a `data-accent` attribute whose variables live in `styles.css`.
- **`ReportView` is pure.** It takes data and renders HTML: no hooks, no router `Link`, no fetching, in-page anchors as `<a href="#...">`. That is what lets the app and the public Worker route render the same component.
- Never log or return the share token after creation; never log the signing secret. `TMPDIR=$HOME/.cache/tmp`. No sudo. Never push without asking. Migrations are generated, never edited. Never commit `.env`.

## Scope and non-goals

In scope: branding settings and logo; the report page and its model and projection; consultant edits; frozen snapshots, share links, withdrawal and a public Worker route; print-to-PDF; the CSV register; owner hints as stored rule metadata; the entry point and first-run help.

Not in scope: re-run diff and "fixed / new / unchanged" (M6); a server-rendered PDF; PPTX, Slides or Sheets export; screenshots or any raw evidence in the report; AI text in the report; client accounts; emailing the link; a custom accent hex; client logos; link analytics beyond "opened n times, last opened"; scheduled reports; templates or languages other than English.

## Decisions

| Question | Decision | Why |
|---|---|---|
| Live or frozen shared report | **Frozen snapshot, created by publishing.** The Report tab is a live draft and says "Unpublished changes" when the **publication identity** (model hash plus logo byte digest) differs from the latest snapshot's | Triage, notes and branding change after a consultant sends something; a regulator- or contract-facing record needs a date and must not move. The public path is one indexed row read. Cost: a new version needs a new link; old links show "A newer version was published on <date>" until revoked or deleted |
| Public transport | **A Worker route family under `/r/`** (`GET /r/<token>` document, `GET /r/<token>/logo`), no server function and no hydration | See "Public route: transport contract". Server functions are reachable at `/_serverFn/*` by anyone, outside `/r/` (`server.ts` falls through to the TanStack handler), where `read` cannot emit 410 or report headers. A Worker route owns status, headers, caching and abuse controls in one function |
| Page labels | **Aliases by default** ("Page 1 (start page)", "Journey from Page 1"). A per-report **disclosure level** `detailed` (checkbox "Print page paths and ad-platform IDs", default off, with a disclosure and a list of the exact strings that would print) prints the entered path without query or fragment and numeric destination IDs | Paths can hold names and reset tokens and no heuristic separates them (`/customers/Alice-Smith`, `/reset-password/a1b2c3...`). The decision belongs to a person who can read the list. Cost: a report with aliases is less specific; the consultant can say more in a note or switch the level on |
| Stored messages | `check_result.message`, inconclusive reasons and capture error text are **never printed** (appendix and findings use stored static titles, counts and a fixed list of failure labels) | `invalid-currency.ts:30` repeats arbitrary currency values, `lost-across-navigation.ts:129` puts paths and queries into reasons, `rules/index.ts:86` embeds capture error messages |
| PDF | **Browser print of the same page through a print stylesheet.** Server-side `page.pdf()` deferred | "PDF: print stylesheet or the capture engine" below |
| Summary headlines | **Deterministic, from stored findings** plus one coverage line; the consultant can replace the summary with their own text | Templates over stored `title`, counts and scenario labels are repeatable and need no model |
| AI text in the report | **Not in M5** | Per-finding, cached under a policy and written for the consultant, not the client; revisit as an explicit toggle (open question 7) |
| Owner hint | **Static rule metadata `owner`**, stored on `check_result` and `finding`; per-finding override in `report_finding_edit` | The owner is a property of the rule's fix. Old rows are null ("Owner not assigned") until overridden. `RULES_VERSION` stays "3": no verdict changes |
| Hide from report | **"Leave out of the detail"**: the detail and plan entry are omitted from the **public model**; the score, arithmetic and counts still include the finding and the appendix lists its title. The hidden finding's detail exists only in a **consultant-only side payload**, never in the model or the snapshot | A report that drops a finding while printing a score that counts it would be dishonest. Keeping the detail out of the model by construction (not by CSS) is what lets consultant mode dim and edit it without leaking it |
| Read consistency | `buildReport` runs in **one `REPEATABLE READ`, read-only transaction**; publication rebuilds inside that read, then takes the publication lock and compares an **input stamp** (see "Publication") before writing | One snapshot for every table (findings, triage, edits, branding, hits) without holding the lock during the slow R2 reads |
| Accent colour | **Eight presets** at 4.5:1 or better both ways (script in Task 2) | Constrained choices cannot produce an unreadable report; no inline style |
| Logo | PNG, JPEG or WebP, at most 512 KB, magic bytes, SHA-256 stored, immutable object keys, shown to the public only through the share-authorized `/r/<token>/logo` | Security; Task 3 |
| Share link lifetime | 7, 30 (default), 90 days or never; revocable; the full link is shown **once** | Only the hash is stored |
| Report forced light | `.report-paper` re-declares the light variables | `docs/ui.md`: light is the default for reports |

### PDF: print stylesheet or the capture engine

| | Print stylesheet (browser Save as PDF) | `page.pdf()` in `apps/browser` |
|---|---|---|
| Fit with the engine | none needed | The engine has one route, `POST /capture` (`apps/browser/src/server.ts`). A deployed public app origin passes `checkUrl` (it is not a private address), so no exception is needed there; **local dev** needs `ALLOW_PRIVATE_NETWORKS=true`. A new `/pdf` route, its contract and an image rebuild are still new work |
| Capacity | the viewer's own browser | The engines (`BROWSER_ENGINES`) are shared FIFO through `AdmissionGate` with up to 168-run audits; a PDF would queue behind captures or need its own admission class |
| Delivery | one click | Worker to engine to R2 to download, with its own timeout and failure states |
| Proven | needs Chromium and Firefox print checked (Task 9) | The container image has never run (`docs/roadmap.md`, M1) |
| Fidelity | `@page` and `break-*` honoured by both; browser headers and footers print the URL (and the token) unless the user turns them off | Deterministic, page numbers, no URL |

**Decision:** print stylesheet for M5. The toolbar has "Save as PDF" (`window.print()`) with the help line "Turn off headers and footers in the print dialog so the link is not printed". **Deferred (recorded in `docs/vision.md`):** `POST /pdf` on the engine, which needs (a) a single-use, short-lived print URL minted by the Worker, (b) its own admission class so PDFs never wait behind audits, (c) a size and time cap, (d) the container image proven first, (e) `ALLOW_PRIVATE_NETWORKS` only in local dev. Cloudflare Browser Rendering is the alternative.

## Data model

New tables in `packages/db/src/report-schema.ts`, exported from `packages/db/src/index.ts`; owner columns in `rules-schema.ts`. Each is added by the task that needs it, with `pnpm --filter @repo/db db:generate` then `pnpm db:migrate`. **Every new table's `org_id` references `organization(id)` `on delete cascade`** (the existing audit tables have no such reference, `audit-schema.ts:24`, so an organization deletion cascades from the new tables themselves, not through the audit).

```ts
// Task 10. Additive: the audit-level version counter (high-water mark; survives deletion of snapshots).
audit.report_version_seq: integer not null default 0

// Task 1. Additive, nullable.
check_result.owner: text          // 'consent-platform' | 'tag-manager' | 'developer' | null
finding.owner: text               // copied by finish from the newest version's check results

// Task 2/3. One row per organization; a missing row means BRANDING_DEFAULTS.
org_branding: orgId text PK references organization on delete cascade,
              agencyName text not null,          // 1..80
              accent text not null,              // an id from ACCENTS
              footerText text,                   // <= 300, plain text
              showPoweredBy boolean not null default true,
              logoKey text,                      // Storage key, unique per upload, never overwritten
              logoType text,                     // sniffed: image/png | image/jpeg | image/webp
              logoSha256 text,                   // hex of the stored bytes, computed on the server at upload
              updatedBy text not null, updatedAt timestamptz not null
// BRANDING_DEFAULTS exported once from server/branding-data.ts (the ai-policy-data.ts pattern).

// Task 8. The consultant's text and disclosure choice, per audit. Written only by saveReportEdit / saveFindingEdit.
report_edit: auditId uuid PK references audit on delete cascade,
             orgId text not null references organization on delete cascade,
             summary text,                       // <= 2000
             detail text not null default 'standard',   // 'standard' | 'detailed' (the disclosure level)
             updatedBy text not null, updatedAt timestamptz not null
report_finding_edit: auditId uuid references audit on delete cascade,
             orgId text not null references organization on delete cascade,
             ruleId text not null,               // no foreign key to finding, like finding_triage
             note text,                          // <= 1000
             hidden boolean not null default false,
             owner text,                         // override of the stored owner hint
             updatedBy text not null, updatedAt timestamptz not null,
             PK (auditId, ruleId)

// Task 10. A frozen report.
report_snapshot: id uuid PK defaultRandom,
             orgId text not null references organization on delete cascade,
             auditId uuid not null references audit on delete cascade,
             version integer not null,           // from audit.report_version_seq under the publication lock; never reused
             modelVersion integer not null,
             model jsonb not null,               // the public ReportModel, validated on write and read
             publicationHash text not null,      // sha256(canonicalJson(model without generatedAt) + "\n" + logoSha256 ?? "")
             logoKey text,                       // copy under reports/<orgId>/<snapshotId>/logo
             logoType text, logoSha256 text,
             publishedBy text not null, publishedAt timestamptz not null defaultNow,
             unique (auditId, version), index (orgId, auditId)
// Task 10. Outbox for organization deletion (no foreign key by design: it must outlive the cascade).
report_file_cleanup: orgId text not null, key text not null, primary key (orgId, key)
// Task 11. A link to one snapshot.
report_share: id uuid PK defaultRandom,
             orgId text not null references organization on delete cascade,
             snapshotId uuid not null references report_snapshot on delete cascade,
             tokenHash text not null unique, label text, expiresAt timestamptz,
             createdBy text not null, createdAt timestamptz not null defaultNow,
             revokedAt timestamptz, revokedBy text,
             viewCount integer not null default 0, lastViewedAt timestamptz,
             index (orgId, snapshotId)
```

- **Retention policy.** A published snapshot lives until (a) an owner, an admin or its publisher deletes that version in the Report tab ("Delete this version": the row, every link to it and the logo copy), or (b) the organization is deleted. There is no automatic expiry: the point is a dated record, and links expire on their own. A deleted version's links answer 404 at once. Version numbers are never reused: they come from a counter on the audit (`audit.report_version_seq`, below) that deletion does not decrease.
- **Storage cleanup.** Logo objects (`branding/...`, `reports/...`) are not cascaded by the database. Deleting a version deletes the row first, then the object (best effort, logged); an orphaned object is **inaccessible** because every read goes through a row (`/r/<token>/logo` looks the snapshot up; branding logos go through the signed `/files/` route for the consultant's own preview only). **Organization deletion** (Better Auth 1.7.10, `crud-org.mjs`: `beforeDeleteOrganization({ organization, user }, ctx)`, then `adapter.deleteOrganization`, then `afterDeleteOrganization({ organization, user }, ctx)`; the after-hook receives nothing from the before-hook and the rows are already gone) uses a small durable outbox instead of shared request state: `report_file_cleanup (orgId text not null with no foreign key, key text not null, primary key (orgId, key))`. The before-hook (`makeAuth` gains two closures built in `auth-live.ts` from the `Database` and `Storage` services, so `auth.ts` does not import the runtime) replaces that organization's outbox rows with the current `logo_key`s of `org_branding` and `report_snapshot`; if it throws, the deletion does not happen. The after-hook deletes those objects and then their outbox rows, and also drains any outbox row whose organization no longer exists (a crashed earlier cleanup). If the deletion itself fails after the before-hook, nothing was removed: rows and logos stay usable, the outbox rows are inert (they are drained only for an organization that is gone) and the next before-hook replaces them. There is no "hook unavailable" fallback: the hooks exist in the installed version.
- **Immutable logo reference.** A logo upload writes a new key (`branding/<orgId>/<uuid>`) and updates the branding row; the old object is deleted after the update. Publication copies the key it read in its consistent snapshot, verifies the SHA-256 of the copied bytes equals `logoSha256`, and writes the copy under the new snapshot's id. If the source object has been replaced and deleted in the meantime, the copy fails and publication retries from the read (below).
- `viewCount` and `lastViewedAt` are updated at most once a minute per link; link-preview bots open links too, so the number says "opened".

## The report

### `ReportModel`

One `Schema`-validated JSON document, `REPORT_MODEL_VERSION = 1`, in `apps/web/src/lib/report-model.ts` with the pure functions that make it (`headlinesOf`, `actionPlanOf`, `publicationHashOf`, `reportDate`). It has no internal ids (no run, org, audit or user ids; rule ids are public), no user names, and **no hidden-finding detail**.

```ts
interface ReportModel {
  modelVersion: 1
  generatedAt: string                      // ISO; excluded from the publication hash
  detail: "standard" | "detailed"
  branding: { agencyName: string; accent: AccentId; footerText: string | null
              showPoweredBy: boolean; logoDigest: string | null }     // sha256 hex of the logo bytes, part of identity
  cover: { clientName: string; siteName: string; host: string; auditedAt: string
           scope: { pages: string[]; scenarios: string[]; viewports: string[]; journey: boolean; clickIds: boolean } }
  summary: { source: "generated" | "author"; text: string | null; score: HealthScore
             withoutAccepted: number | null                   // the Overview's score excluding accepted risks
             runHealth: { startFailed: boolean; startPage: string | null     // a page label per the disclosure level
                          startReason: string | null; unfinishedRuns: number; incomplete: boolean }
             counts: { critical: number; warning: number; info: number; couldNotCheck: number; acceptedRisk: number; fixed: number }
             headlines: string[]
             coverage: { evaluatedRuns: number; totalRuns: number; unresolvedRules: number; bannerUncertainRuns: number }
             worst: { ruleId: string; severity: Severity; title: string; scopeLine: string } | null }
  method: { rulesVersions: string[]; scoreVersion: number; runs: { complete: number; partial: number; failed: number }; mixedVersions: boolean }
  consent: { scenarios: string[]; rows: ConsentRow[] }
  findings: ReportFinding[]
  leftOut: { ruleId: string; title: string }[]
  actionPlan: { owner: OwnerId | null; items: { ruleId: string; severity: Severity; title: string; firstStep: string }[] }[]
  appendix: { couldNotCheck: { ruleId: string; checkTitle: string; runs: number }[]
              notEvaluated: { page: string; scenario: string; viewport: string; reason: string }[]
              rules: { ruleId: string; title: string; area: string; severity: Severity; version: string
                       pass: number; fail: number; couldNotCheck: number; notApplicable: number }[] }
}
interface ConsentRow { vendor: string
  cells: { scenario: string
           runs: { total: number; complete: number; partial: number; none: number }       // capture coverage, as matrix-data.ts
           outcomes: Record<string, number>                                                 // run.consent.outcome counts
           runsWithHits: number; hits: number
           choice: { observed: number; hitsBefore: number; hitsAfter: number } }[] }      // observed = runs with outcome accepted/rejected and an action time
interface ReportFinding { ruleId: string; severity: Severity; area: string; title: string; why: string; fix: string[]
  owner: OwnerId | null; ownerSource: "rule" | "author" | "none"; failingRuns: number; knownRuns: number
  pages: string[]; scenarios: string[]; bannerUncertainRuns: number
  triage: { status: "open" | "accepted_risk" | "fixed"; reason: string | null }; note: string | null
  evidence: { caption: string; rows: EvidenceRow[] } | null }
```

**The consultant side payload.** `buildReport` returns `{ model, consultant }`. `consultant` is never serialised into a snapshot, a share response or the CSV's public columns: `{ edits: { summary, detail }, hiddenFindings: ReportFinding[] (full detail, including note and evidence), changesSincePublished: boolean }`. The consultant view merges `model.findings` and `consultant.hiddenFindings` for display only. The snapshot writer takes `model`, and the Schema for `ReportModel` has no field that could carry hidden detail.

**Deterministic order** (all comparisons by code-unit order, never `localeCompare`, because the hash must be identical on every runtime): findings by severity rank, then `failingRuns / knownRuns` descending, then `ruleId`; `cover.scope.pages` in the audit's configured order; scenarios none, accept, reject, gpc; viewports desktop, mobile; `consent.rows` by `vendorRank` (GA4, Google Ads, Meta, TikTok), then label; `findings[].pages` in configured order; `findings[].scenarios` in scenario order; `findings[].fix` as stored; `evidence.rows` sorted by their canonical JSON; `leftOut` by `ruleId`; `actionPlan` groups consent platform, tag manager, developer, not assigned, items as findings; `appendix.couldNotCheck` by `checkTitle` then `ruleId`; `appendix.notEvaluated` by run ordinal; `appendix.rules` by area order (`AREAS` keys) then `ruleId`; `method.rulesVersions` by the numeric version compare `findingsFrom` uses; `headlines` as derived. `canonicalJson` (`@repo/llm`, `digest.ts:117`) sorts object keys only, so arrays must already be in this order before hashing.

### How it is built (`apps/web/src/server/report-data.ts`)

`buildReport(orgId, auditId)` is one Effect in **two phases**. **Phase 1 reads the database only**, in a single transaction opened with `set transaction isolation level repeatable read read only` as its first statement (`atomically` in `server-fn.ts` pins the connection; the isolation statement is the first query, so the snapshot is taken after it) and committed before phase 2. A database error in phase 1 is fatal and nothing in phase 1 catches it (a failed statement aborts a PostgreSQL transaction and a caught error does not restore it). **Phase 2 touches no database**: it reads captures from `Storage` through the tolerant reader, builds the evidence rows and the projection, and returns. Captures are immutable per run, so reading them after the commit is consistent with the snapshot, and no database connection is held while R2 is read. Phase 1:

1. `findingsOf`, `healthScore` and the audit/site/client/config reads; `org_branding` (or defaults); `report_edit`, `report_finding_edit`; triage comes with `findingsOf`. All at one snapshot, so a triage change, a note and a logo replacement made while the build runs are either all in or all out.
2. **Consent summary**: one grouped query over `hit` joined to `run` (`vendor, scenario, count(distinct run_id), count(*), count(*) filter (where after_consent_action)`), joined with per-scenario `run` facts exactly as `matrix-data.ts` derives them: `coverageOf(status)` (complete, partial, none) and `run.consent.outcome`. `choice.observed` counts runs whose outcome is accepted or rejected with an action time; `hitsAfter` is only meaningful over those runs (`after_consent_action = false` can mean no action happened, `audit-schema.ts:140`), so a cell with `observed = 0` is worded "No choice was observed, so hits are not split" rather than "0 hits after the choice".
3. **Evidence candidates (phase 1)**: through the shared run assembly (Task 6), for each failing finding the first five failing runs in run order with their `captureKey`, shape, the failing check's evidence refs and the `hit` rows those refs name (rows only; `hit.params`, `hit.url` and `hit.ids` are not selected into the report path). **Evidence (phase 2)**: for each finding, try the candidates in order; each capture goes through a **request-scoped cache** (`Map<captureKey, Effect memoised once>`) and the **tolerant reader** `readCaptureTolerant(captureKey): Effect<Option<CaptureResult>>`, which cannot fail: a null key gives `none` ("missing"); `Storage.get` returning `Option.none` gives `none` ("missing"); a `StorageError` from `get` is caught and gives `none` ("storage"); a failure reading the body (`Effect.tryPromise` over `new Response(body).text()`) gives `none` ("body"); a decode failure of `Schema.fromJsonString(CaptureResult)` gives `none` ("decode"). Each `none` logs one `Effect.logWarning` with the reason code and the run id, never content. This is built from `Storage.get` before any `orDie`; the strict `readCapture` (Explain, Evidence panel) is unchanged. The first candidate that yields at least one evidence row wins; if none does, `evidence` is `null` and the card says "Evidence is not available for this finding in the stored captures." Publication treats transient failures differently from absence: when any capture read for a candidate ended in `storage` or `body` (not `missing` or `decode`), `publish` fails with "Some evidence could not be read; try again" instead of freezing a snapshot whose evidence (and therefore content hash) depends on a passing outage; the live Report tab still renders with the evidence it has.
4. Headlines, action plan, appendix, left-out list as in the sections below, plus `withoutAccepted` and `runHealth` from the **shared score-summary function** extracted from `getOverview` (Task 4; `runHealth.startReason` goes through `runReasonLabel`, which uses only the static `FAILURE_TEXT` and `ERROR_TEXT` maps of `audit-labels.ts` and never falls back to an error message the way `runReason` does); then `assertProjected(model, detail)`.
5. Returns `{ model, consultant, stamp }` where `stamp` is the input stamp: the audit's `finishedAt`, `org_branding.updatedAt` and `logoSha256`, `report_edit.updatedAt` and `report_edit.detail`, and the maximum `updatedAt` plus row count of `report_finding_edit` and of `finding_triage` for the audit.

Dates are formatted by `reportDate(iso)` as `28 October 2026 (UTC)`, the same on server and browser and in print.

### Publication (Task 10)

`publishReport(auditId)` (used by sharing):

1. `buildReport` (consistent snapshot) outside any lock; compute `publicationHash`.
2. Open a read-committed transaction, `select ... from audit where id = $1 for update` (the **publication lock**), re-read the **stamp** with the same small query. If it differs from step 1's stamp, roll back and go to step 1 (at most three times, then `Invalid("The report changed while it was being published. Try again.")`).
3. Still under the lock: read the latest snapshot's `publicationHash`. If equal, **reuse it** (no new row, no copy) and return its id. Two concurrent identical publishes therefore produce one snapshot; the second one waits on the lock and reuses.
4. Otherwise allocate the version from the audit's **high-water counter**: `update audit set report_version_seq = report_version_seq + 1 where id = $1 returning report_version_seq` under the lock (the counter lives on the `audit` row, which the workflow never writes in that column, and is never decremented, so deleting version 2 does not make the next publication version 2 again; reuse of an identical snapshot does not increment it), copy the logo (the key and digest from step 1) to `reports/<orgId>/<newSnapshotId>/logo` with the digest verified, insert the snapshot, commit. If the copy fails with the source missing, roll back and retry from step 1; if the copy succeeded and the insert or commit then fails, delete the copy (`Effect.ensuring`, best effort). A crash between copy and commit leaves an inaccessible orphan object.
5. The audit row lock serialises publishers of one audit only; it does not stop edits, which is why step 2 compares the stamp.

## Public route: transport contract

A Worker route (`apps/web/src/server/report-route.ts`, added to `workerRoutes` before the TanStack fallback) owns everything under `/r/`:

| Request | Result |
|---|---|
| `GET /r/<token>` active | 200, `text/html; charset=utf-8`, the report as static HTML (`renderToStaticMarkup(<ReportView>)` inside a small document shell with the app stylesheet `<link>`, `<meta name="robots">`, and one `<script src="/report-print.js">` for the Print button), logo as `<img src="/r/<token>/logo">`. No hydration payload and no router state. **The one place the token appears in the body is that same-origin `src` path** (one occurrence per logo `<img>`, none when there is no logo) |
| `GET /r/<token>` revoked | 410, a short page: "This report link has been turned off." and "Ask <agency> for a new link." (agency name from the snapshot, text only) |
| expired | 410, "This report link has expired." plus the same line |
| unknown, malformed, snapshot deleted | 404, one fixed body, identical for all causes |
| `GET /r/<token>/logo` | the same state checks; 200 with the stored bytes, `Content-Type` from the stored sniffed type, `Content-Disposition: inline`, `Cache-Control: no-store`, `nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`; 404 or 410 as above; 404 when the snapshot has no logo |
| Any other method, or any other path under `/r/` | 405 with `Allow: GET`, or 404, with the same headers |

Headers on **every** response from this route, success or failure, built by one function `reportResponse(status, body, extra)`: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow, noarchive`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy: default-src 'none'; style-src 'self'; img-src 'self'; script-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. No `unsafe-inline` anywhere because nothing is hydrated. `robots.txt` disallows `/r/`.

- **Status by state is decided in one place**, so a direct request, a reload after revocation, a back-button return and a copied URL all see the current state (`no-store` also keeps browsers from restoring a cached page, and there is no client-side data function that could serve stale data).
- **Token secrecy vs the page (one rule).** The token is a bearer secret in the URL. Its only other appearance is the absolute same-origin path in the logo `<img src="/r/<token>/logo">`, which the browser sends back to the same origin and which `Referrer-Policy: no-referrer` and the same-origin CSP keep from other sites. It is not in any script, other attribute, `<link>`, `<meta>`, JSON, response header (`Location` is never issued) or cross-origin URL. Our own code never logs the path; Cloudflare-side logs may, so a leaked link is handled by revoking it. The check is a count: the token occurs exactly as many times as there are logo images, all inside `src=`.
- **Abuse controls.** Shape check (`looksLikeShareToken`) before any database access; uniform 404; GET only; one indexed lookup per request; the view counter writes at most once a minute per link; a Cloudflare rate-limiting rule on `/r/*` at deploy (the binding in `infra/alchemy.run.ts` is an unverified spike, open question 5). Because there is no server function, `/_serverFn/*` exposes nothing about shares to anonymous callers (management functions all need a session).
- **Spike first (Task 12).** The route imports the stylesheet URL the way the root route does (`import appCss from "@/styles.css?url"`) and renders with `react-dom/server`; confirm both work from a Worker route module under `pnpm dev` and a `pnpm build`. Fallback if the `?url` import cannot be used outside the router: render the document from a TanStack route with the same headers applied by a wrapper in `server.ts`, status set with `setResponseStatus`, and a server function that is a thin call to the same Effect; the contract table above still has to hold for the direct `/_serverFn` request, which then needs the same checks (state, headers, uniform errors) and is verified separately.

## Share links: security design

- **Token.** `zr1_` + 43 base64url characters from 32 bytes of `crypto.getRandomValues` (256 bits). Pure helpers in `packages/core/src/share-token.ts` (`generateShareToken`, `hashShareToken` = SHA-256 hex via Web Crypto, `looksLikeShareToken`). Only the hash is stored (`unique`); the token is returned once by `createShareLink`, never logged, never listed.
- **Lookup.** Shape check, hash, select link + snapshot by `token_hash`, then compare stored and computed hash with `crypto.subtle.timingSafeEqual` (Workers) as defence in depth; the indexed equality on the hash is the real gate.
- **States.** As in the transport table. Revoked and expired are 410 (a holder of a once-valid token learns only that it ended); unknown and deleted are 404.
- **Exposure.** The route returns the public model only; no org, audit, user or link id, no consultant payload, no edit timestamps.
- **Revocation** is immediate for the document **and** the logo (both look the link up on every request; neither is cacheable). A copied logo URL has no independent life: there is no signed URL for the public logo.
- **Management.** Create, list, revoke and delete are server functions behind `requireSession`, `membership` and `auditInOrg` / `shareInOrg`; ids of another organization are a 404. Revoking twice is a no-op. Listing never returns the token or hash.
- **Consultant text** is plain text (`whitespace-pre-line`, `overflow-wrap: anywhere`), never HTML, markdown or auto-linked.
- **Logo upload** (Task 3). First bytes: PNG `89 50 4E 47 0D 0A 1A 0A`, JPEG `FF D8 FF`, WebP `RIFF....WEBP`; anything else is rejected, SVG and GIF included. The stored type is the sniffed one; the client's type and file name are ignored. At most 512 KB, enforced before `Storage.put`. SHA-256 of the bytes stored in `logo_sha256`. Key `branding/<orgId>/<crypto.randomUUID()>`. The consultant's own previews (Settings, Report tab) use a 5-minute signed `/files/` URL; **the public never receives a signed URL**. Residual risk, stated in Settings: a JPEG may carry EXIF (including location) which we do not strip, and a logo is visible to anyone with a live report link.
- **CSV.** Cells that start with `=`, `+`, `-`, `@`, tab, carriage return or line feed are prefixed with `'`; RFC 4180 quoting; UTF-8 BOM; `Content-Disposition: attachment`, `nosniff`, `Cache-Control: private, no-store`; session resolved with `Auth.sessionFromHeaders`, `activeMembership`, `auditInOrg` in that order, anything else 404. Page columns use the same disclosure level and labels as the report; no stored messages.

## Performance targets (168 runs)

Seeded with `docs/plans/2026-10-27-m4-matrix-overview-llm/seed-max.sql` plus 19 findings with check results and real captures for at least ten distinct failing runs. Local Postgres, warm, p95 of 20 calls, measured on the serialized response. R2 latency is not measured (as in M4).

|---|---|
| `getReportDraft` / `buildReport` (REPEATABLE READ read, capture reads at most 5 per finding and deduplicated) | <= 1500 ms, <= 150 KB JSON; capture reads counted and reported (expected <= 19 distinct when evidence is present) |
