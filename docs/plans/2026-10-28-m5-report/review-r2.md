# M5 plan review, round 2 (GPT-6.1 Sol, high) — verdict: needs rework

Most round 1 concerns are addressed, but the disclosure guard prevents valid reports from rendering, and several revised contracts conflict.

1. **Blocker — `assertProjected` rejects required output.** (P:22, 151, 173, 159.) Every logo adds a 64-character hex `branding.logoDigest`, which the guard rejects. Detailed mode permits numeric IDs and paths that may contain encoded emails or tokens, which it also rejects. Legitimate Google Ads IDs can exceed its ten-digit threshold (`packages/llm/src/vocab.ts:10–14`). Change: field-specific validation (exact digest validation, reviewed static vocabulary, explicit author fields, disclosure-aware path and ID validators), still fail-closed for unexpected fields. Verify: branded Standard reports and the documented Detailed hostile cases render; an unsafe value in a prohibited field still fails.
2. **Should fix — version numbers are reused after deletion.** (P:132, 227, 404.) `max + 1` reuses 2 after publishing 1 and 2 and deleting 2; the audit schema has no counter (`audit-schema.ts:56–73`). Change: an audit-level high-water mark under the publication lock that survives deletion. Verify: delete the highest version, then every version; later publications keep increasing.
3. **Should fix — token-free HTML contradicts the logo contract.** (P:250, 260, 424.) `<img src="/r/<token>/logo">` puts the token in the body. Worker routing is fine (`server.ts:20–24`, `routes.ts:7–12`). Change: explicitly allow the token in the same-origin logo URL and correct the secrecy checks, or a trailing-slash document URL with relative `src="logo"`. Verify: inspect the HTML with branding on.
4. **Should fix — `ReportModel` cannot reproduce main's Overview score.** (P:14, 176–181, 235, 339.) Main computes `withoutAccepted` and `runHealth.incomplete` separately (`overview.ts:165–173`); `HealthScore` lacks them (`health-score.ts:39–55`). The explainer uses interactive `Collapsible` (`$auditId.overview.tsx:423,468–481`), conflicting with the hook-free static view. Change: both projected fields; extract the shared calculation and a pure arithmetic body; keep interactive wrappers in the app. Verify: accepted-risk and unreachable-start audits match the Overview in draft, snapshot and printed public report with JavaScript off.
5. **Should fix — organization cleanup destroys logos before deletion succeeds.** (P:133, 400.) Better Auth 1.7.10 runs `beforeDeleteOrganization` → delete → `afterDeleteOrganization` (`better-auth/dist/plugins/organization/routes/crud-org.mjs:282–290`); only invitation handling is wired now (`auth.ts:21`). Change: collect keys before, remove objects after successful deletion, pass keys to the after-hook without shared mutable request state; drop the "hook unavailable" fallback. Verify: fail deletion after the before-hook (rows and logos still usable); a successful deletion removes rows and attempts cleanup.
6. **Should fix — a query failure poisons the tolerant evidence read.** (P:210, 214, 360.) A failed statement aborts the enclosing PostgreSQL transaction and catching does not restore it; `readCapture` turns storage and decode failures into defects (`audit-data.ts:57–64`), so typed recovery around it does nothing. Change: a tolerant reader from `Storage.get` before `orDie`, with defined handling for missing, storage, body-read and decode failures; database failures stay fatal. Verify: missing object, storage error, malformed JSON each give the agreed result with no "transaction aborted".
7. **Nit — impossible or misleading checks.** P:394 needs a 200-character agency name but P:319 caps it at 80; P:404 checks `report_share` before Task 11 creates it; P:384 calls an author-written summary "Generated from the findings". Change: valid maxima, move the share-cascade check after Task 11, correct provenance.
