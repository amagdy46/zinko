# M5 plan review, round 1 (GPT-6.1 Sol, high) — verdict: needs rework

The direction is sound, but publication privacy, deletion and snapshot identity need corrected contracts before implementation.

1. **Blocker — the minimiser does not guarantee publication-safe data.** (P:20, 140, 180, 183, 300, 360.) `packages/llm/src/digest.ts:145` removes queries but keeps `/customers/Alice-Smith` and password-reset tokens; `packages/llm/src/vocab.ts:10` permits numeric identifiers that can be phone numbers. Stored messages are not safe: `packages/rules/src/rules/coverage/invalid-currency.ts:30` repeats arbitrary currency values; `packages/rules/src/rules/clickids/lost-across-navigation.ts:129` puts paths and queries in an inconclusive reason; `packages/rules/src/index.ts:86` embeds capture error messages. Change: a report-specific disclosure projection for every field, aliases by default, exclude unreviewed diagnostic messages, explicitly disclose any permitted paths or identifiers. Verify: hostile names, encoded emails, domestic phones, reset tokens, query-bearing journey URLs and capture errors across draft JSON, snapshot, HTML, PDF and CSV.
2. **Blocker — organization deletion leaves public snapshots accessible.** (P:102–122, 206.) Snapshot and share `orgId` columns have no organization foreign key; `packages/db/src/audit-schema.ts:24` has none either, so the audit cascade does not help. Change: generated cascading organization references and storage cleanup; a way to withdraw or delete published content whose data the organization later removes (indefinite immutable retention is currently the only policy). Verify: delete a scratch organization after publication: links 404, rows gone, copied logos inaccessible.
3. **Blocker — logo replacement is invisible to the content hash.** (P:107, 136–137, 184, 340.) The model has only `hasLogo`, so replacing a logo keeps the hash and "Create link" reuses the old branded snapshot. Change: include a stable logo byte digest in publication identity (not signed URLs or snapshot keys); deterministic ordering for every model array (canonical JSON sorts object keys only, `packages/llm/src/digest.ts:117`). Verify: replacement flags a change; identical bytes and unchanged rebuilds do not.
4. **Should fix — publication lacks a coherent-read contract.** (P:178–184, 234, 340–343.) Locking the audit serializes version allocation but not branding, notes or triage writes (`server-fn.ts:115` has transactions; triage is joined separately, `findings-data.ts:138`). Change: one consistent database read and an immutable logo reference, compare the latest hash under the publication lock, cleanup and retry on copy failure; concurrent identical publications reuse one snapshot (contradicts the "distinct versions" check). Verify: delayed concurrent publish, edit and logo replace produce coherent snapshots, no duplicates, no dangling logos.
5. **Should fix — `digestOf` unchanged cannot meet the evidence contract.** (P:180, 218–223, 299–303.) `explain.ts:138` selects all failing runs, `:159` loads every capture, `:194` returns a finished digest; a missing capture throws (`audit-data.ts:57`). Change: extract shared run assembly with explicit selection and request-scoped capture reuse; keep Explain's all-run behaviour; the report selects one resolvable case and tolerates unavailable evidence. Verify: count object reads at 168 runs with distinct captures, remove one capture, Explain hashes unchanged.
6. **Should fix — consent summary drops partial observations and failed choices.** (P:153–155, 179, 195, 293.) The matrix keeps complete/partial/missing counts and outcomes (`matrix-data.ts:140`); partial banner-error captures stay usable (`rules/src/index.ts:73`); `afterConsentAction=false` can mean no action happened (`audit-schema.ts:140`). Change: keep coverage and outcome counts; distinguish "no choice observed" from zero hits after a choice; partial is not "Not captured". Verify: no-CMP, failed action, partial with hits, mixed coverage, against SQL.
7. **Should fix — revocation does not revoke issued logo URLs.** (P:123, 210, 213.) `/files/` checks only signature expiry (`storage-route.ts:36`), so a copied 24-hour URL outlives revocation (and EXIF); headers allow private caching (`storage-security.ts:90`). Change: serve report logos through a share-authorized endpoint with `no-store`, or narrow the revocation promise. Verify: keep the logo URL, revoke, expire or delete the share, request it.
8. **Should fix — the public endpoint needs its own transport contract.** (P:205–210, 349–353, 405.) Server functions are served by the TanStack fallback outside `/r/` (`server.ts:24`); `read` handles not-found but neither 410 nor report headers (`server-fn.ts:75`). Change: status, headers and abuse controls for direct server-function calls as well as documents; separate token secrecy from the impossible rule that hydration never contains its own token. Verify: raw document and direct data requests in every state, including cached navigation and reload after revocation.
9. **Should fix — hidden findings cannot be rendered as specified.** (P:156–157, 190, 329–333.) The model drops their detail but consultant mode must dim the cards and offer edits. Change: consultant-only hidden detail beside the public model, with a projection that excludes it from snapshots. Verify: hide, reload, restore, edit; public JSON lacks notes and evidence.
10. **Should fix — print is verified before the content most likely to overflow.** (P:193, 320–323, 330, 383.) Task 8 precedes 2,000-character summaries and 1,000-character notes; `break-inside: avoid` cannot hold an oversized card; the shell keeps its desktop grid when the sidebar is hidden (`app.tsx:98`). Change: repeat print acceptance after edits, reset the shell layout, let oversized cards split, specify wrapping. Verify: maximum text, long unbroken strings, 19 findings, four scenario columns, both themes, both browsers.
11. **Should fix — several acceptance checks give false evidence.** (P:248, 293, 333, 363.) Ids are `clickid.*`, not `clickids.*`; `meta-before-consent` has no post-reject Meta hit (fixtures README:83); starting another audit does not replay the first audit's `finish` (`Audit.ts:630`); Python CSV parsing does not show spreadsheet formula safety. Change: correct expectations, recompute the same audit, open formula cases in a real spreadsheet (every dangerous prefix and a leading LF).

Keeping `RULES_VERSION` "3" for additive owner metadata is right. Task 1 should scope "first non-null" to the newest version's rows. Split Task 10 into publication and storage consistency, and link management.
